Speed is addictive

Code arrives faster than anyone can read it. Reviews become a skim, copy-paste replaces refactoring, and the process loses its shape. Nobody decides this; it just happens.

AI doesn't fix a team; it amplifies what's already there.

The problem

Writing code got cheap. Understanding it did not.

Pull requests balloon

A reviewer who once read 100 lines now gets 800 lines of confident boilerplate.

Approval turns into a formality

Nobody reads 800 lines closely. People skim and hope CI catches the rest.

Nobody owns the design

When it breaks at 3 a.m., no one on the team actually designed that code.

Where I'm coming from

What running an AI lab taught me

I tried a chat of AI agents reviewing each other

  • Different models (Copilot reviewing Claude) really did add a second opinion.
  • One model in many roles felt like voices in one head: mostly noise.
  • Agents fixed corner cases no user would hit, and the codebase kept growing.
  • Token costs grew faster than the value, so it could not scale.
What I kept

Context management. Give each session exactly what it needs, hard-code the rest, keep a person on the decisions.

Chasing every finding leads to over-engineering: extra abstraction layers, defensive code, and tests for cases that can't happen.
